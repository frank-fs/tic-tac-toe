# Frank 7.3.2 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `TicTacToe.Web` from Frank 7.2.0 to 7.3.2, adopt the new `negotiate { }` content-negotiation builder for the httpRange-14 conneg on `GET /games/{id}`, replace the hand-rolled `Link` response headers with Frank core's shared `link` mechanism, and replace the three hand-rolled discovery documents (JSON Home, ALPS, RDF/JSON-LD) with `Frank.JsonHome`, `Frank.Alps`, and `Frank.Rdf` respectively — one package at a time, each landing as its own tested commit.

**Architecture:** No architectural change to the app's shape (still one `webHost { }`, one `resource { }` per route). Each task swaps ONE hand-rolled mechanism for its Frank-library equivalent while preserving the wire contract the existing test suite locks in (`WireSemanticsTests`, `DiscoveryContentTests`, `SurfaceCellTests`), except where a library's design forces a disclosed, deliberate behavior change — every such change is called out in the task that introduces it, not discovered later.

**Tech Stack:** F# / .NET 10, ASP.NET Core, Frank 7.3.2 (`Frank`, `Frank.Datastar`, `Frank.Auth`, `Frank.OpenApi`, `Frank.JsonHome`, `Frank.Alps`, `Frank.Rdf`), NUnit + Playwright integration tests.

## Global Constraints

- Every task ends green: `dotnet build`, `dotnet test test/TicTacToe.Engine.Tests/`, `dotnet test test/TicTacToe.Web.Tests/` all pass before moving to the next task.
- Work happens in a worktree per `CLAUDE.md` — never commit directly on `main`. One commit per task (or per step group within a task where noted).
- Frank package versions: `Frank`, `Frank.Datastar`, `Frank.Auth`, `Frank.OpenApi` move from `7.2.0` → `7.3.2`. `Frank.JsonHome`, `Frank.Alps`, `Frank.Rdf` are added at `7.3.2` (first-ever publish of those three per Frank's own release notes — no prior version to reconcile).
- `Frank.Provenance` and `Frank.Validation` are explicitly **out of scope** — nothing in `TicTacToe.Web` hand-rolls PROV-O provenance or SHACL validation today, so there is nothing to migrate. Not added.
- Several deliberate, disclosed behavior changes ride along with this migration (each is called out again inline at the task that introduces it — this is the index):
  1. **Task 1 (core upgrade):** Frank.OpenApi 7.3.2 moves the OpenAPI document from `/openapi/v1.json` (7.2.0) to `/.well-known/openapi.json` — confirmed by reading `src/Frank.OpenApi/WebHostBuilderExtensions.fs:16` (`openApiRoutePattern = "/.well-known/openapi.json"`), not called out in prose in the 7.3.2 release notes. `Program.fs`'s `useOpenApiGuard` path-matches `"/openapi"` today; left unfixed, `TICTACTOE_OPENAPI_ENABLED=0` would silently stop gating anything the moment the core packages bump, before Task 4/5 even start. Task 1 fixes the path check. Separately, `useOpenApi` also registers a `rel="service-desc"` Link contribution the same unconditional, app-wide way `useJsonHome`/`useAlps` do (see item 3) — gated by neither `Surface.Sd` nor `TICTACTOE_OPENAPI_ENABLED`. Task 1 introduces the scrub mechanism (item 3) specifically because this leak exists from the bare core upgrade alone, independent of anything JSON-Home/ALPS-related.
  2. **Task 5 (ALPS):** `reset`'s ALPS `type` changes from `idempotent` to `unsafe` — the hand-rolled profile mislabeled it (each reset creates a brand-new game resource; that is not idempotent), and Frank.Alps's startup `binds` validation (`idempotent` → PUT/DELETE only) would fail host startup on the existing POST binding otherwise. (`take-seat` and `make-move` are the same wire action — both bind cleanly to the one `POST /games/{id}` handler via two `binds` calls on it, since `HandlerDefinition`'s metadata is a list and `EndpointSurface.allDescriptors` reads it via `GetOrderedMetadata<Descriptor>()`, plural; no document-content loss here.)
  3. **Task 1 + 4 + 5 (OpenApi/JsonHome/ALPS):** `useOpenApi`/`useJsonHome`/`useAlps` each register their `rel="service-desc"`/`rel="home"`/`rel="profile"` `Link` header contribution as an unconditional, app-wide provider (confirmed by reading `src/Frank.OpenApi/WebHostBuilderExtensions.fs`, `src/Frank.JsonHome/WebHostBuilderExtensions.fs`, and `src/Frank.Alps/AlpsDocument.fs` in the Frank repo — all three hard-code `fun (_: HttpContext) -> Seq.singleton { ... }`, ignoring the request entirely). Since none of the three libraries exposes a way to gate that per-request, Task 1 adds a single `IStartupFilter`-based scrub middleware (`DiscoveryLinkScrubStartupFilter`) that strips `rel` values from the `Link` header per the flag that's supposed to govern each one — `service-desc` when `TICTACTOE_OPENAPI_ENABLED` is off (true from Task 1 onward), `home`/`profile` when `Surface.Sd` is off (those two markers become live once Tasks 4 and 5 respectively wire `useJsonHome`/`useAlps` — inert no-ops before that). This preserves the "Sd hides all discovery signals" invariant `WireSemanticsTests`/`FloorSurfaceWireTests` depend on, and the existing "TICTACTOE_OPENAPI_ENABLED hides the discovery surface leak" invariant the `useOpenApiGuard` doc comment already states as this app's intent. When `Sd` is on, `rel="home"`/`rel="profile"` now legitimately appear on *every* response (not just the three endpoints that used to carry them) — this widening is accepted per explicit user decision (see conversation) and is not tested against anywhere, so it does not break the suite.
  4. **Task 6 (RDF):** `Frank.Rdf`'s `Doc.writeJsonLd` only emits **expanded-form** JSON-LD (no `@context`, every predicate/type as an absolute IRI, one flat top-level node-object per subject). The hand-rolled `gameJsonLd` emitted compact JSON-LD with a `@context` and a nested `numberOfPlayers` object. The wire body of `GET /games/{id}/type` changes shape; `WireSemanticsTests`' assertion on that body is updated accordingly.
  5. **(final review, retroactive)** `/.well-known/home.json`'s resource catalog permanently lost its `"tag:tictactoe,2026:profile"` entry. Investigated: `AlpsOptions.Rel` only controls the ALPS document's own advertised HTTP `Link` rel (already correctly "profile"), not the app's JSON-Home catalog key, and `Frank.JsonHome`'s `rel`/`hrefVar` custom operations only exist on the `resource { }` CE builder, not composable onto the `Resource` value `AlpsDocument.documentResource` returns. No clean fix available in the app's own code — worth reporting upstream to the Frank maintainers (a consumer wanting both `useAlps`'s auto-mounted document AND a JSON-Home catalog entry for it currently cannot express that).
  6. **(final review, retroactive)** `Frank.JsonHome` 7.3.2 serializes its resource template keys as camelCase (`hrefTemplate`/`hrefVars`) instead of the hyphenated form the JSON Home spec (draft-nottingham-json-home §4) and the app's old hand-rolled document used (`href-template`/`href-vars`) — a library-level wire-format regression, not something this app's code controls. Worth reporting upstream.
  7. **(final review, retroactive)** The two well-known documents (`/.well-known/alps.json`, `/.well-known/home.json`) went from `requireAuth`-gated (pre-migration, 302/challenge if unauthenticated) to anonymously accessible (post-migration, since the Frank-mounted resources don't carry `requireAuth`). Independently verified: NOT an affordance/authorization leak — `AlpsDocument`'s own per-request authorization filtering means an anonymous caller sees only the 7 semantic (non-transition) descriptors with all `binds`-bound transitions pruned, and anonymous JSON Home is literally `{"resources":{}}`. Confirmed intentional per the library's progressive-disclosure design, low risk — but it's a real, undisclosed change to when the app's discovery surface becomes visible, worth recording as intentional.
  8. **(final review, retroactive)** The `Allow: GET, OPTIONS` header the old hand-rolled `profile`/`wellKnownHome` handlers used to set on their own GET responses is gone on the Frank-mounted equivalents (though `OPTIONS` requests to those same paths still correctly return `Allow` via the app's existing `useOptionsDiscovery` mechanism, so this is a partial, low-impact gap, not a full loss).

- [x] **Step 5: Add `DiscoveryLinkScrubStartupFilter`**

`useOpenApi` registers its `rel="service-desc"` `Link` header contribution as an unconditional, app-wide provider (`src/Frank.OpenApi/WebHostBuilderExtensions.fs`'s `serviceDescLinkProvider`, hard-coded `fun (_: HttpContext) -> Seq.singleton { ... }`, ignoring the request). `TICTACTOE_OPENAPI_ENABLED=0` (Step 4's guard) blocks the *document endpoint* but does nothing about this *header*, which would otherwise keep advertising a 404'd document on every response during an "OpenAPI off" test run — the same class of leak `openApiEnabled()`'s own doc comment already says this app needs to be able to shut off.

This must be an `IStartupFilter`, not a `plugBeforeRouting` middleware. `WebLink.useAppWideLinks` (`src/Frank/WebHostBuilder.fs:52`) is spliced as the very first thing inside `WebHostBuilder.Run`'s `.Configure(...)` — before every `plugBeforeRouting` entry a consumer can add. `HttpResponse.OnStarting` callbacks fire in LIFO order (last registered, first executed), so `useAppWideLinks`' callback — being registered first, for every request — is *structurally guaranteed to fire last* among callbacks reachable from `plugBeforeRouting`/`plug`. The only way to register a callback that fires *after* it (so it can see, and edit, what it already appended) is to register even earlier, which requires wrapping the entire `.Configure(...)` pipeline from *outside* via `IStartupFilter` (the same technique `Frank.JsonHome`'s own `DuplicateRelStartupFilter`/`HrefVarStartupFilter` use, for the unrelated reason of needing the fully-built endpoint list).

Its marker list is built once per app start from two independent flags — `TICTACTOE_OPENAPI_ENABLED` (live from this task) and `Surface.Sd` (inert until Tasks 4-5 wire `useJsonHome`/`useAlps`; there is nothing to strip yet, so those markers are harmless no-ops here). Add, near `useOpenApiGuard`:

```fsharp
/// Strips Link-header rel values that Frank 7.3.2's useX operations register as unconditional,
/// app-wide contributions with no per-request hook of their own -- one rel per flag that's
/// supposed to gate that discovery signal: "service-desc" (useOpenApi) when
/// TICTACTOE_OPENAPI_ENABLED is off; "home" (useJsonHome, wired in a later task) and "profile"
/// (useAlps, wired in a later task) when Sd is off. See the doc comment on useOpenApiGuard/Step 4
/// above for why this must be an IStartupFilter and not a plugBeforeRouting middleware.
type private DiscoveryLinkScrubStartupFilter(surface: Surface) =
    interface IStartupFilter with
        member _.Configure(next: Action<IApplicationBuilder>) =
            Action<IApplicationBuilder>(fun app ->
                let markers =
                    [ if not (openApiEnabled ()) then yield "rel=\"service-desc\""
                      if not surface.Sd then
                          yield "rel=\"profile\""
                          yield "rel=\"home\"" ]

                if not (List.isEmpty markers) then
                    app.Use(fun (ctx: HttpContext) (next2: RequestDelegate) ->
                        task {
                            ctx.Response.OnStarting(fun () ->
                                match ctx.Response.Headers.TryGetValue("Link") with
                                | true, values ->
                                    let kept =
                                        values
                                        |> Seq.filter (fun v -> not (markers |> List.exists v.Contains))
                                        |> Array.ofSeq
                                    if kept.Length = 0 then
                                        ctx.Response.Headers.Remove("Link") |> ignore
                                    else
                                        ctx.Response.Headers.["Link"] <- Microsoft.Extensions.Primitives.StringValues kept
                                | false, _ -> ()
                                Task.CompletedTask)
                            |> ignore
                            do! next2.Invoke ctx
                        }
                        :> Task)
                    |> ignore
                next.Invoke app)
```

Register it in `configureServices`, right after the existing `.AddSingleton<Surface>(Surface.fromEnvironment ())` call so it can depend on that already-registered singleton:

```fsharp
    services.AddSingleton<IStartupFilter>(fun sp ->
        DiscoveryLinkScrubStartupFilter(sp.GetRequiredService<Surface>()) :> IStartupFilter)
    |> ignore
```

Add `open Microsoft.AspNetCore.Hosting` to `Program.fs`'s `open` list (for `IStartupFilter`) — it is not present today.

- [x] **Step 1: Replace `getGame` with `getGameHtml` in `Handlers.fs`**

Replace lines 399-430 (the whole `getGame` function) with:

```fsharp
/// GET /games/{id} — the default representation: always HTML, the game board or the 404 page.
/// Registered as negotiate{}'s wildcard "*/*" case in Program.fs, and reused directly by
/// getGameLdJson below whenever So is off or there's no game to redirect from.
let getGameHtml (ctx: HttpContext) =
    task {
        let supervisor = ctx.RequestServices.GetRequiredService<GameSupervisor>()
        let surface = surfaceOf ctx
        let gameId = ctx.Request.RouteValues.["id"] |> string
        let basePath = routePrefix ctx

        // GET is safe: no subscription side effect here. Every game is subscribed for
        // broadcasts at creation (createGame / startup / reset), so a read need not register one.
        // Read from the supervisor's cached state (TryGetState): never messages the game actor,
        // so a just-deleted game returns None (404) instead of hanging on a Stopped actor.
        match supervisor.TryGetState(gameId) with
        | Some result ->
            ctx.Response.Headers.CacheControl <- "no-cache, private"
            ctx.Response.Headers.Vary <- "Cookie"
            match gameAllow result with
            | allow -> ctx.Response.Headers.Append("Allow", allow)
            do! renderGamePage ctx gameId result None
        | None ->
            ctx.Response.StatusCode <- 404
            ctx.Response.Headers.CacheControl <- "no-cache, private"
            ctx.Response.Headers.Vary <- "Cookie"
            ctx.Response.ContentType <- "text/html; charset=utf-8"
            let element = notFoundPage |> layout.html ctx
            do! Render.toStreamAsync ctx.Response.Body element
    }

/// httpRange-14: an RDF request on the thing -> 303 See Other to its describing document
/// (/games/{id}/type), but only when So is on — with So off there is no describing document to
/// redirect to, so the request falls through to the ordinary HTML representation instead.
/// Registered as negotiate{}'s "application/ld+json" case in Program.fs.
let getGameLdJson (ctx: HttpContext) =
    task {
        let surface = surfaceOf ctx
        if not surface.So then
            do! getGameHtml ctx
        else
            let supervisor = ctx.RequestServices.GetRequiredService<GameSupervisor>()
            let gameId = ctx.Request.RouteValues.["id"] |> string
            let basePath = routePrefix ctx
            match supervisor.TryGetState(gameId) with
            | Some _ ->
                ctx.Response.StatusCode <- 303
                ctx.Response.Headers.Location <- Microsoft.Extensions.Primitives.StringValues $"{basePath}/{gameId}/type"
            | None -> do! getGameHtml ctx
    }
```

Note: this drops the `if surface.Sd then setDiscoveryHeaders ...` and `if surface.So then setDescribedByHeader ...` lines from the old `getGame` — those move to Task 3 (`link` on the `gameById` resource). The `Allow` header stays here since Frank core's `link` mechanism has no equivalent for `Allow`.

### Task 5: Frank.Alps — replace the hand-rolled ALPS profile

Adds `Frank.Alps`, authors the same descriptor tree as typed `Descriptor` values, mounts it via `useAlps`, wires `binds` on the endpoints that can validly carry it, and removes `Discovery.alpsProfile` (the JSON string), `Handlers.profile`, and `profileResource`.

Two modeling gaps surfaced while researching this task (both already folded into the code below, restated here for context):

1. **`href`-only nested references.** The hand-rolled JSON nests bare `{"href": "#player"}` stubs (no `id`) inside e.g. `square-state`'s `descriptor` array to mean "this field references `player`." `Frank.Alps.Descriptor.Id` is mandatory, so a truly id-less stub isn't representable. The port instead nests a small named stub descriptor whose own `Id` is synthetic (`"square-state-player"`) and whose `InheritsFrom` (set via the `href` combinator) points at `player` — this still serializes with a top-level `"href"` key (confirmed by reading `src/Frank.Alps/Serialization.fs:92`), so `DiscoveryContentTests`' `hrefsOf` helper (which only checks for an `href` property, not the absence of `id`) keeps passing. `nestedIdsOf`, which collects **every** nested child's `id`, now also picks up these synthetic stub ids — `square-state`'s and `outcome`'s `nestedIdsOf` assertions are updated in Step 5 below to include them.
2. **`binds` and the live-served document.** `AlpsDocument`'s `documentHandler` (`src/Frank.Alps/AlpsDocument.fs`) only serves transitions with a `binds`-bound, authorized endpoint — an unbound transition is dropped from the *served* document (logged as a startup warning, not a failure). `take-seat` and `make-move` are the same wire action (the hand-rolled doc's own text says so) — both are POST `/games/{id}`, so both are `unsafe`-typed and both can legally `binds` to that one endpoint. `HandlerDefinition`'s metadata is a list (`HandlerDefinition.addMetadata` appends, confirmed in `src/Frank/HandlerBuilder.fs`), and `EndpointSurface.allDescriptors` reads it via `Metadata.GetOrderedMetadata<Descriptor>()` — plural, all matches, not just the first — so `handler { handle Handlers.makeMove; binds Discovery.makeMove; binds Discovery.takeSeat }` binds both, and both are validated and served. No document-content loss; no unbound-transition warning for either. `reset`'s `type` is corrected from `idempotent` to `unsafe` to match its real behavior (each reset call creates a brand-new game resource — not idempotent) and to satisfy `AlpsDocument.validate`'s method/type check (`idempotent` requires PUT/DELETE; the endpoint is POST).

```fsharp
open Frank.Rdf

/// The game's RDF description as schema.org/Game JSON-LD (So). Absolute IRIs are built from the
/// request scheme+host so every named thing is a dereferenceable HTTP URI; zero blank nodes;
/// sameAs links to Wikidata + DBpedia. Two triples with the same (subject, predicate) and
/// different objects (the two sameAs targets) is exactly how RDF represents a multi-valued
/// property -- Doc.writeJsonLd's expanded form renders that as a JSON array for the predicate.
let gameDoc (gameUri: string) : Doc =
    let game = Node.Iri gameUri
    let players = Node.Iri $"{gameUri}#players"

    rdf {
        prefix "schema" "https://schema.org/"

        about (
            describe game {
                typ "schema:Game"
                propertyString "schema:name" "Tic-tac-toe"
                propertyString "schema:description" "A two-player m,n,k (3,3,3) game: place three of your marks in a row to win."
                propertyNode "schema:numberOfPlayers" players
                propertyNode "schema:sameAs" (Node.Iri "http://www.wikidata.org/entity/Q210339")
                propertyNode "schema:sameAs" (Node.Iri "http://dbpedia.org/resource/Tic-tac-toe")
            }
        )

        about (describe players { typ "schema:QuantitativeValue"; propertyInt "schema:value" 2 })
    }
```

```fsharp
    task {
        let surface = surfaceOf ctx
        let supervisor = ctx.RequestServices.GetRequiredService<GameSupervisor>()
        let gameId = ctx.Request.RouteValues.["id"] |> string
```
